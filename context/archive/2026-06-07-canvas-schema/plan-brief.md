# Canvas Schema — Plan Brief

> Full plan: `context/changes/canvas-schema/plan.md`

## What & Why

Create the Supabase database schema that all product slices depend on: a `canvases` table storing the 9 BMC blocks as JSONB, a `share_links` table for read-only sharing, RLS policies enforcing per-user isolation, and TypeScript types for the whole codebase. Nothing downstream (dashboard, AI fill, critique, sharing) can be built until this migration exists.

## Starting Point

Supabase is wired (`src/lib/supabase.ts`) and auth is working (`src/middleware.ts`), but no domain migrations exist and `src/types.ts` is absent. The `supabase/migrations/` directory was empty.

## Desired End State

A single migration applies cleanly, two tables exist with RLS enabled and nine policies active, and `src/types.ts` exports `Canvas`, `CanvasBlocks`, and `ShareLink` types. Any downstream slice can import the types and query the tables immediately.

## Key Decisions Made

| Decision                 | Choice                     | Why (1 sentence)                                                    | Source |
| ------------------------ | -------------------------- | ------------------------------------------------------------------- | ------ |
| Block storage shape      | JSONB column on `canvases` | One row per canvas, no joins, fits the speed goal                   | Plan   |
| `updated_at` maintenance | DB trigger                 | Never stale regardless of which code path writes the row            | Plan   |
| PIN storage              | `pin_hash text` (nullable) | Correct security posture; PIN not exposed if table is read directly | Plan   |
| TypeScript types         | Included in this change    | S-01 and S-02 can import immediately; trivial effort                | Plan   |
| Canvas name nullability  | Nullable `text`            | S-02 fills it on first AI save; no placeholder needed               | Plan   |
| Delete mode              | Hard delete                | No restore requirement in PRD; simpler queries everywhere           | Plan   |
| Share links anon RLS     | Stubbed now (expiry check) | Avoids a second migration when S-04 ships                           | Plan   |

## Scope

**In scope:** `canvases` table, `share_links` table, `updated_at` trigger on both, RLS with per-op policies for authenticated owners, anon SELECT stub on `share_links`, `src/types.ts` with `Canvas` / `CanvasBlocks` / `ShareLink`.

**Out of scope:** Normalized `canvas_blocks` table, soft delete, PIN comparison logic, seed data, Edge Functions, any API routes.

## Architecture / Approach

One SQL migration file creates everything atomically. The `blocks` JSONB column uses `Partial<CanvasBlocks>` in TypeScript because a new canvas starts empty; S-02 fills all 9 keys. The share-link token is a 32-byte random hex string generated by `pgcrypto`. RLS owner policies on `share_links` join through `canvases` (no direct `owner_id` column).

## Phases at a Glance

| Phase                 | What it delivers                                        | Key risk                                                         |
| --------------------- | ------------------------------------------------------- | ---------------------------------------------------------------- |
| 1. Supabase Migration | Both tables, trigger, RLS, 9 policies — applied cleanly | First migration in project; `npx supabase db reset` must succeed |
| 2. TypeScript Types   | `src/types.ts` with all entity types                    | Type shapes must match SQL schema exactly                        |

**Prerequisites:** Local Docker running (`npx supabase start` works), `.env` / `.dev.vars` has valid `SUPABASE_URL` and `SUPABASE_KEY`.
**Estimated effort:** ~1 session across 2 phases.

## Open Risks & Assumptions

- `pgcrypto` extension is assumed available in the Supabase project (it is enabled by default on hosted Supabase and local dev).
- PIN hashing (bcrypt) is deferred to the application layer in S-04; the migration only stores the hash column.

## Success Criteria (Summary)

- `npx supabase db reset` exits 0 and both tables appear in Supabase Studio with all 9 RLS policies active.
- `npm run build` and `npm run lint` pass with `src/types.ts` present.
- A cross-user INSERT attempt into `canvases` is rejected by RLS.
