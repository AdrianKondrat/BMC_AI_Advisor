# AI-Generated BMC Fill Implementation Plan

## Overview

Implement the S-02 slice: a `/canvas/new` page where a founder types their business idea, triggers AI generation of all 9 BMC blocks via OpenRouter (GPT-4o, structured JSON output), and is redirected to `/canvas/[id]` — a canvas editor with click-to-edit blocks that auto-save on blur. The "Create your first canvas" dashboard CTA is activated and each existing canvas card gets an "Open" link.

## Current State Analysis

- `canvases` table exists with `blocks jsonb` and `name text` (nullable). No `idea` column yet.
- `src/types.ts` exports `Canvas`, `CanvasBlocks`, `BMCBlockKey`, `CanvasSummary` — all from F-01/S-01.
- `src/pages/api/canvases/[id].ts` exports only `DELETE`. No POST or PATCH canvas endpoints exist.
- `src/components/CanvasList.tsx` renders the list with a disabled "Create your first canvas" CTA; no canvas-row links to an editor.
- `OPENROUTER_API_KEY` and `AI_PROVIDER` are already declared in `astro.config.mjs` env schema.
- No canvas editor page exists. No canvas create page exists.

## Desired End State

- `/canvas/new` shows an idea-input form. Submitting it calls `POST /api/canvases`, which calls OpenRouter, inserts the canvas, and returns the canvas ID. The React island then navigates to `/canvas/${id}`.
- `/canvas/[id]` server-renders the canvas and mounts a React island showing the BMC 5-column grid. Clicking a block activates an inline textarea; blurring saves via `PATCH /api/canvases/[id]`.
- Dashboard: canvas rows link to `/canvas/[id]`; the CTA links to `/canvas/new` (both empty-state and non-empty-list).
- Canvas name and idea text are stored in the DB (name generated by AI as part of the structured output).

### Key Discoveries

- `src/lib/supabase.ts:6` — `createClient(requestHeaders, cookies)` factory; use in both API routes and Astro pages.
- `src/middleware.ts:4` — `PROTECTED_ROUTES` array; add `/canvas` to protect editor and creation routes.
- `src/pages/api/canvases/[id].ts` — existing DELETE route; add PATCH export to the same file.
- `lessons.md` rule: always add `.eq('owner_id', user.id)` on Supabase mutations; do not rely solely on RLS.
- `lessons.md` rule: never edit committed migration files; create a new migration for the `idea` column.
- `astro.config.mjs` env schema already declares `OPENROUTER_API_KEY` (server-only, secret) — importable from `astro:env/server`.

## What We're NOT Doing

- No streaming AI output (SSE or chunked) — single-call JSON with loading state.
- No canvas rename in this slice (FR-003 rename deferred; canvas is named by AI at creation).
- No single-block re-prompt (FR-009 is parked).
- No `AI_PROVIDER` switching logic — OpenRouter is hardcoded as the provider.
- No pagination, search, or sort on the dashboard list.
- No loading skeleton on the dashboard list (SSR-delivered).
- No toast library — inline status indicators only.

## Implementation Approach

**Creation flow:** User visits `/canvas/new` → types idea → `NewCanvasForm` React island POSTs to `/api/canvases` → server calls `generateBMCCanvas(idea)` in `src/lib/services/ai.ts` (OpenRouter, GPT-4o, strict JSON schema: `name` + 9 BMC block strings) → on success, INSERT canvas row → return `{ id, name, blocks }` → React island navigates to `/canvas/${id}`.

**Edit flow:** `/canvas/[id].astro` fetches canvas server-side → passes to `CanvasEditor` React island → user clicks a block cell → inline textarea activates → on blur, React calls `PATCH /api/canvases/${id}` with the full `blocks` object → "Saved ✓" indicator shown briefly.

**Error path:** AI failure returns 500 from the API route with no canvas row created. `NewCanvasForm` shows an inline error message and preserves the idea text for retry.

## Open Risks & Assumptions

- **PRD NFR deviation:** PRD §Non-Functional says idea text "not retained in operator-accessible storage after the session ends." Storing `idea` in `canvases` is a conscious deviation, accepted for future single-block re-prompt capability (FR-009). Owner acknowledges.
- **AI latency:** GPT-4o typically takes 5–15 s for a canvas-sized structured output. The loading state on the form is the only wait indicator — ensure it is prominent.
- **Structured output reliability:** GPT-4o with `json_schema` strict mode is reliable. If parsing fails, return 500 and let user retry; no partial-fill logic.

## Phase 2: POST /api/canvases (Create + AI Generate)

### Overview

A single endpoint accepts the founder's idea text, calls OpenRouter with a strict JSON schema (10 fields: `name` + 9 BMC blocks), creates the canvas row, and returns the result. If the AI call or JSON parsing fails, no canvas row is created and 500 is returned.

### Changes Required

#### 1. Install openai npm package

**File**: `package.json` (via npm install)

**Intent**: Use the OpenAI-compatible SDK to call OpenRouter, gaining typed responses and edge-runtime support.

**Contract**: `npm install openai` — the `openai` package v4+ supports Cloudflare Workers edge runtime.

#### 2. AI service module

**File**: `src/lib/services/ai.ts`

**Intent**: Encapsulate the OpenRouter call and structured-output parsing, keeping the API route free of SDK details.

**Contract**:

- Exports `generateBMCCanvas(idea: string): Promise<{ name: string } & CanvasBlocks>`
- Creates an `OpenAI` client with `baseURL: 'https://openrouter.ai/api/v1'` and `apiKey: OPENROUTER_API_KEY` (from `astro:env/server`)
- Calls `client.chat.completions.create` with:
  - `model: 'openai/gpt-4o'`
  - `response_format: { type: 'json_schema', json_schema: { name: 'bmc_canvas', strict: true, schema: <see below> } }`
  - System message: instructs the model to fill each of the 9 BMC blocks with 2–4 concise, idea-specific bullet points and provide a short (3–6 word) canvas title as `name`
  - User message: the raw `idea` string
- JSON schema has 10 required string fields — `name` plus all 9 `BMCBlockKey` values — with `additionalProperties: false`
- Returns the parsed object; throws on API error or parse failure (caller handles)

#### 3. POST /api/canvases route

**File**: `src/pages/api/canvases/index.ts`

**Intent**: Accept `{ idea }`, call the AI service, insert the canvas row, and return `{ id, name, blocks }`. If the AI call throws, return 500 without inserting a row.

**Contract**:

- `export const prerender = false`
- Exports `POST: APIRoute`
- Auth guard: returns `new Response(null, { status: 401 })` if `context.locals.user` is absent
- Validates body with zod: `{ idea: z.string().min(10).max(2000) }`; returns 400 with JSON error on failure
- Calls `generateBMCCanvas(idea)` — on throw, returns 500
- Supabase INSERT: `{ owner_id: user.id, name: generated.name, blocks: <9-block object>, idea }` — RLS `WITH CHECK (owner_id = auth.uid())` enforces ownership; the explicit `owner_id` field in the insert is the canonical guard
- Returns `Response.json({ id, name, blocks }, { status: 201 })` on success

### Success Criteria

#### Automated Verification

- Build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification

- Authenticated POST with a valid idea (≥ 10 chars) returns 201 and a canvas row appears in Supabase Studio with `name`, all 9 `blocks` keys, and `idea` populated
- Unauthenticated POST returns 401
- POST with `idea` shorter than 10 characters returns 400
- POST with a non-JSON body or missing `idea` key returns 400

## Phase 3: PATCH /api/canvases/[id] (Block Update)

### Overview

Extend the existing `[id].ts` route with a `PATCH` handler so the `CanvasEditor` can persist block edits. Saves the entire `blocks` object in one Supabase update.

### Changes Required

#### 1. Add PATCH export to existing route

**File**: `src/pages/api/canvases/[id].ts`

**Intent**: Let the canvas editor persist block edits by PATCHing the full `blocks` object for the authenticated owner's canvas.

**Contract**:

- Add `export const PATCH: APIRoute` alongside the existing `DELETE`
- Auth guard: 401 if no user
- UUID validation: same regex as in `DELETE`
- Parse JSON body; validate with zod: `{ blocks: z.record(z.enum([...all 9 BMCBlockKey values...]), z.string()) }` — all 9 keys required; returns 400 on failure
- Supabase update: `.from('canvases').update({ blocks, updated_at: new Date().toISOString() }).eq('id', id).eq('owner_id', context.locals.user.id)` — explicit owner filter per `lessons.md` rule; if no rows matched, return 404
- On Supabase error: return 500
- On success: return `Response.json({ updated_at: <value> }, { status: 200 })`

### Success Criteria

#### Automated Verification

- Build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification

- Authenticated PATCH with valid `blocks` updates the canvas row in Supabase Studio and returns 200 with `updated_at`
- PATCH with another user's canvas ID returns 404 (owner filter excludes the row)
- PATCH with an invalid UUID returns 400
- Unauthenticated PATCH returns 401

## Phase 4: React Components

### Overview

Two React islands: `NewCanvasForm` (idea input, loading state, error handling) and `CanvasEditor` (5-column BMC grid, click-to-edit, blur save). Both are pure React — no Astro-specific APIs.

### Changes Required

#### 1. NewCanvasForm component

**File**: `src/components/NewCanvasForm.tsx`

**Intent**: Let the founder enter their idea, trigger generation with a clear loading state, and recover from errors without losing the idea text.

**Contract**:

- Props: none
- State: `idea: string`, `status: 'idle' | 'loading' | 'error'`, `errorMessage: string`
- A `<textarea>` for idea input (placeholder: "Describe your business idea…") and a "Generate my canvas" `<Button>`
- On submit: set `status` to `'loading'`; POST `{ idea }` to `/api/canvases`; on 201 response navigate to `/canvas/${data.id}` via `window.location.href`; on non-2xx or network error set `status: 'error'` and `errorMessage` from the response body (or a generic fallback)
- Loading state: button text becomes "Generating…" and is `disabled`; textarea is `disabled`
- Error state: inline red error message below the form; button re-enabled, idea text preserved

#### 2. CanvasEditor component

**File**: `src/components/CanvasEditor.tsx`

**Intent**: Render the BMC canvas as a living document — a visual 5-column grid where clicking a block activates inline editing and blurring saves the full blocks state.

**Contract**:

- Props: `{ canvas: Canvas }`
- State:
  - `blocks: CanvasBlocks` — initialized from `canvas.blocks`; all 9 keys default to `''` if absent
  - `activeBlock: BMCBlockKey | null` — the currently edited block
  - `saveStatus: 'idle' | 'saving' | 'saved' | 'error'`
- **Grid layout**: CSS grid, 5 columns × 3 rows, approximating the classic BMC:
  - Rows 1–2: Key Partners (col 1, `row-span-2`) | Key Activities/Key Resources (col 2, each 1 row) | Value Propositions (col 3, `row-span-2`) | Customer Relationships/Channels (col 4, each 1 row) | Customer Segments (col 5, `row-span-2`)
  - Row 3: Cost Structure (`col-span-2`) | Revenue Streams (`col-span-3`)
  - Below `md` breakpoint: single-column stack in BMC logical order
- Each block cell: a small label heading (`<h3>`) + content area
  - Not active: `<p>` with the block text; if empty, gray italic "Click to add…" placeholder
  - Active: autofocused `<textarea>` bound to `blocks[key]` via `onChange`
- On cell click: set `activeBlock = key`
- On textarea `onBlur`: set `activeBlock = null`; call `PATCH /api/canvases/${canvas.id}` with the current `blocks` state; set `saveStatus` based on response
- Save-status indicator: small text at the top-right of the editor ("Saved ✓" / "Error saving"); reverts to idle after 2 s using `setTimeout`

#### Automated Verification

- Build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification

- Error state shows the message and preserves idea text; button re-enables for retry

**File**: `src/pages/canvas/[id].astro`

## Testing Strategy

### Manual Testing Steps

1. Sign in → go to `/dashboard` → click "Create your first canvas" (or "New Canvas") → verify redirect to `/canvas/new`
2. Type a business idea (e.g., "A subscription box for artisan coffee from small roasters") → click "Generate my canvas" → verify loading state appears
3. After generation (5–15 s): verify redirect to `/canvas/[id]` with all 9 blocks filled and an AI-generated name
4. In Supabase Studio: confirm canvas row has `name`, all 9 `blocks` keys, and `idea` text
5. Click any BMC block → verify textarea activates with the AI content
6. Edit the text → click outside → verify "Saved ✓" appears → check Supabase Studio for the updated `blocks` value
7. Navigate back to `/dashboard` → canvas appears in the list with the AI-generated name
8. Click "Open" → verify the editor loads with saved edits
9. AI failure simulation: temporarily corrupt `OPENROUTER_API_KEY` in `.dev.vars` → submit idea → verify inline error on `/canvas/new` and idea text is preserved
10. Unauthenticated: open `/canvas/new` and `/canvas/[id]` in an incognito tab → verify redirect to `/auth/signin`

## Performance Considerations

AI generation will take 5–15 s. The `NewCanvasForm` loading state is the only wait indicator — make "Generating…" text prominent and disable the entire form. Block PATCH sends all 9 blocks (~2 KB per call) on each blur event; at MVP scale this is negligible.
