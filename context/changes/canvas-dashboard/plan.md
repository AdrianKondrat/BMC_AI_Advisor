# Canvas Dashboard Implementation Plan

## Overview

Add S-01 to the founder dashboard: a server-rendered list of the user's canvases with per-canvas delete. The list is a React island mounted in `dashboard.astro`; delete uses an AlertDialog for confirmation and optimistic client-side removal.

## Current State Analysis

- `dashboard.astro` is a bare shell — welcome card + sign-out button, no canvas data.
- `canvases` table exists with RLS; owners can SELECT and DELETE their own rows (`context/changes/canvas-schema/plan.md`).
- `src/types.ts` exports `Canvas` (with typed blocks); the list view needs only `id`, `name`, `created_at`, `updated_at`.
- Only `button.tsx` exists in `src/components/ui/`; AlertDialog must be installed via shadcn.
- No React components exist outside `src/components/ui/` yet.
- API routes are auth-only (`src/pages/api/auth/`); no canvas endpoints.

## Desired End State

`/dashboard` shows the user's canvases ordered newest-first. Each row shows the canvas name (or "Untitled canvas" for null), creation date, and a Delete button. Clicking Delete opens an AlertDialog; confirming calls `DELETE /api/canvases/[id]` and removes the row without a full page reload. When no canvases exist an empty state with a disabled "Create your first canvas" CTA is shown. The sign-out button is retained in a page header.

### Key Discoveries

- `context.locals.user` carries the authenticated user; `createClient(request.headers, cookies)` is the established pattern (`src/lib/supabase.ts:1`).
- RLS owner DELETE policy handles authorization silently — the API endpoint only needs to confirm auth and parse the ID.
- `Canvas` type includes `blocks: Partial<CanvasBlocks>` — a lighter `CanvasSummary` type avoids shipping block JSONB to the client for list display.
- `export const prerender = false` required on all API routes (CLAUDE.md convention).
- Existing auth routes (`src/pages/api/auth/signin.ts`) establish the pattern: parse input, call Supabase, return redirect or Response.

## What We're NOT Doing

- No canvas editing or viewing (S-02).
- No search, filter, or pagination — MVP list only.
- No soft-delete or undo.
- No "create canvas" logic — the CTA button is disabled (placeholder for S-02).
- No loading skeleton — SSR delivers the list synchronously.
- No toast notifications — inline error state on delete failure is sufficient.

## Implementation Approach

Three phases in dependency order: API endpoint first (independently testable), React component second (can be developed with fixture props), page wiring third.

Delete flow: React island holds `useState<CanvasSummary[]>` initialized from SSR props → Delete click opens AlertDialog → confirm fires `fetch('DELETE /api/canvases/[id]')` → on 2xx, filter item from state (optimistic removal); on error, surface an inline message.

## Phase 1: DELETE API Endpoint

### Overview

Expose `DELETE /api/canvases/[id]` so the React island can remove a canvas. RLS enforces ownership; the endpoint validates auth and ID format, then delegates to Supabase.

### Changes Required

#### 1. API route

**File**: `src/pages/api/canvases/[id].ts`

**Intent**: Handle authenticated DELETE requests. Returns 401 if unauthenticated, 400 if the ID is not a valid UUID, 204 on success. RLS makes "not found" and "wrong owner" indistinguishable (both are silent no-ops returning 0 rows) — both return 204, which is acceptable for MVP.

**Contract**:

- `export const prerender = false`
- Exports `DELETE: APIRoute`
- Reads `context.locals.user`; returns `new Response(null, { status: 401 })` if absent
- Reads `context.params.id`; validates UUID format with a regex; returns `new Response(null, { status: 400 })` if invalid
- Creates supabase client; calls `.from('canvases').delete().eq('id', id)`
- Returns `new Response(null, { status: 500 })` on Supabase error, `new Response(null, { status: 204 })` on success

### Success Criteria

#### Automated Verification

- TypeScript build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification

- Authenticated `DELETE /api/canvases/<valid-uuid>` for own canvas returns 204 and the row is gone
- `DELETE /api/canvases/not-a-uuid` returns 400
- Unauthenticated request returns 401
- Authenticated `DELETE` of another user's canvas ID returns 204 but does not delete it (RLS silent no-op — verify row still exists in Supabase dashboard)

**Implementation Note**: After completing this phase and all automated verification passes, pause here for manual confirmation before proceeding to Phase 2.

## Phase 2: CanvasList React Component

### Overview

A React island that renders the canvas list (or empty state) and manages the delete interaction. Receives `canvases: CanvasSummary[]` from Astro SSR props.

### Changes Required

#### 1. Install AlertDialog

**File**: `src/components/ui/alert-dialog.tsx` (generated by shadcn)

**Intent**: Install the shadcn AlertDialog component needed for the delete confirmation step.

**Contract**: Run `npx shadcn@latest add alert-dialog`. No manual edits; shadcn writes the file.

#### 2. Add CanvasSummary type

**File**: `src/types.ts`

**Intent**: Add a `CanvasSummary` type for the dashboard list view — avoids including the blocks JSONB payload that `Canvas` carries.

**Contract**: `Pick` of `id`, `name`, `created_at`, `updated_at` from the canvases row type. `name` is `string | null` (matches schema).

#### 3. CanvasList component

**File**: `src/components/CanvasList.tsx`

**Intent**: Renders the canvas list with per-row delete and empty state. Manages its own copy of the list in state so rows can be removed optimistically without a page reload.

**Contract**:

- Props: `{ canvases: CanvasSummary[] }`
- `useState<CanvasSummary[]>` initialized from props
- Each row: `canvas.name ?? 'Untitled canvas'`, formatted `created_at` (`toLocaleDateString()`), Delete button
- Delete button triggers `AlertDialog` with a "Are you sure? This cannot be undone." message
- On confirm: `fetch('/api/canvases/' + id, { method: 'DELETE' })`; on 2xx, remove item from state; on non-2xx, set an inline error string and keep the item
- Empty state (zero items in state): centered icon (e.g. a folder or document emoji), "No canvases yet" heading, `<Button disabled>Create your first canvas</Button>`

### Success Criteria

#### Automated Verification

- TypeScript build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification

- List renders with canvas names and creation dates
- Null-name canvas shows "Untitled canvas"
- Delete button opens AlertDialog; Cancel closes it without removing the row
- Confirming delete removes the row from the list without a page reload
- Deleting the last remaining canvas transitions to the empty state
- "Create your first canvas" button is visually present but non-interactive (`disabled`)

**Implementation Note**: After completing this phase and all automated verification passes, pause here for manual confirmation before proceeding to Phase 3.

## Phase 3: Dashboard Page Wiring

### Overview

Update `dashboard.astro` to fetch the user's canvases server-side and mount `CanvasList` as a React island. Replaces the placeholder shell while retaining the sign-out affordance.

### Changes Required

#### 1. Update dashboard.astro

**File**: `src/pages/dashboard.astro`

**Intent**: Replace the placeholder welcome card with a page header (user email + sign-out) and the `CanvasList` React island. Fetch canvases from Supabase before rendering so the island receives hydrated data and renders without a client-side loading state.

**Contract**:

- Import `CanvasList` from `@/components/CanvasList`
- Create supabase client at the top of the frontmatter; query `canvases` selecting `id, name, created_at, updated_at` ordered by `created_at` descending
- On null supabase or Supabase error, fall back to an empty array (render empty state rather than crashing)
- Page structure: narrow header with `Astro.locals.user.email` and the sign-out POST form; then `<CanvasList client:load canvases={data ?? []} />`

### Success Criteria

#### Automated Verification

- TypeScript build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification

- `/dashboard` renders the canvas list (or empty state if user has no canvases)
- User email and sign-out button are visible in the page header
- Full delete flow works end-to-end from the browser: open dialog → confirm → row disappears
- Unauthenticated visit to `/dashboard` redirects to `/auth/signin` (middleware unchanged — verify no regression)

## Testing Strategy

### Manual Testing Steps

1. Sign in and navigate to `/dashboard` — empty state should appear with a disabled CTA
2. Insert a canvas row directly via Supabase dashboard; refresh `/dashboard` — it should appear in the list
3. Insert a canvas with a null name; verify "Untitled canvas" is displayed
4. Delete the canvas — confirm dialog appears, row disappears on confirm, no page reload
5. Delete all canvases — empty state reappears
6. Sign out and navigate directly to `/dashboard` — should redirect to `/auth/signin`
